# 架构与数据流

项目分开保存课程内容与个人记录；新课需要人工或学习助手查证制作，运行时没有隐藏的模型请求。

```text
官方文档 / 教材 / 固定提交源码
          ↓ 人工或学习助手核实
content/课件.json + web/media/教学媒体
          ↓ 校验
          ├─ import-lesson → 本地 SQLite → 电脑端 App
          └─ courses.json → build_site.py → 静态手机 App
                                              ↓
                                      浏览器 localStorage
```

## 电脑端

`learning_loop.py` 提供命令行、本地 HTTP 服务和学习档案，仅依赖 Python 3.9+ 标准库。默认地址 `http://127.0.0.1:8765`，本地 API 检查请求来源。私人数据在 `data/learning.sqlite3`。

`request-track` 为用户选择的项目或学科建立待备课主线，同主题或同仓库请求复用已有主线；`import-lesson` 导入核验后的教学包。草稿不代表 ready，教材 ready 也不代表学习者已掌握。

GitHub 发现通过公开 API 获取仓库快照，`content/catalog.json` 维护仓库类型与主线分类。≥100,000 Star 门槛只约束发现榜单，不约束手动选题。失败保留缓存，累计 Star 不冒充增长速度。

## 课库与构建

`content/courses.json` 登记课程稳定 ID、标题、主题、学科、类型、可选仓库与 `lesson_file`。课件包含核心思想、案例、预测题、实验、应用、回忆问题和媒体。无代码的学科课使用 `code_insight: null`。

`/media/课程/...` 指向 `web/media/` 下的资源。手机端按当前部署目录解析路径，支持站点根目录和仓库子路径。

构建器不打开私人数据库，只发布登记课件、引用媒体、公开实验、来源许可和运行文件。暂存完成后替换上次成功产物；没有本站构建标记的非空目录不能覆盖。

## 手机端

`web/mobile/` 是静态网页 App，可部署到 HTTPS 托管。它读取构建后的 `courses.json`，共用教学组件展示图、音视频和代码解释。

学习档案在 localStorage，支持导出和验证后导入手机 JSON；导入经用户确认后整体替换，不自动合并。手机与电脑 SQLite 为独立档案，无账号、云同步或学习记录上传接口。

Service worker 缓存整个课程版本，更新时课程和媒体一起切换。准备成功后可离线使用缓存，新课需联网更新。清理浏览器数据会影响记录和缓存。

## 备课与提醒

`skill/learning-loop/` 说明研究、制作、伴学和复习流程，助手从实际项目根目录使用。`daily --refresh` 只生成一次检查结果；持续调度需要单独配置。

可选 Codex 定时任务执行检查、为已选主题备课和提醒复习。网页偏好不能自行更改外部调度器。手机导出的每日复习日历需要用户导入，提醒由日历设置决定；关闭网页后没有后台推送。

## 学习状态

选择、听讲与观看不创建证据。用户提交自己的实验、应用或总结后才进入复习，先作答再看参考答案和自评，提前复习不延长原计划。助手不得代答或自评。

电脑端掌握状态要求实践与多个日期的到期回忆证据；手机端记录呈现实际提交，不把播放进度当作能力认证。

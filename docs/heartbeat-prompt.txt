每天检查我的项目与学科学习循环，使用中文。先读取 skill/learning-loop/SKILL.md，再运行 python3 learning_loop.py state 和 python3 learning_loop.py daily --refresh。以项目持久化状态和配置时区为准；发现数据超过 24 小时才更新公开 GitHub 候选。

刷新后如 discovery.unclassified 有新仓库，按 skill 先核实官方说明并使用 import-catalog 补充类型与主线，再重新读取 state；无法确认的保持待分类，不猜测开源许可。候选使用 star 至少 100,000、许可元数据可识别的开源软件项目，按当前累计 star 排序，排除后端认定已学主线并合并重复主题，呈现最多二十项供我选择。累计 star 不是近期增速；数据失败时注明缓存时间，不编造数据或补足条目。100,000 star 只约束发现榜单，不限制我手选项目或学科。仅讨论过某技术不等于已学会。

每次最多为一条我已选择且仍 queued 的主线备课。没有已选主线就不要替我选择或开启新课程。备课时读取 skill 的 references/teaching.md：项目课核实官方说明和固定 commit 核心源码，学科课读取权威教材或原始研究。生成含核心机制、图解预测题、真实中文音频、案例、小实验、应用验收和回忆问题的严格 JSON 包；音频覆盖范围与实测时长如实说明。项目源码逐行解释，无代码的学科课使用 code_insight: null。媒体先制作和核验，再用 validate-lesson 验证，最后按真实 track ID 用 import-lesson 导入。来源或媒体未完成时保留 queued，不用占位内容冒充完整课程。导入后读取 state 核验；生成教材不能记作我已掌握。

优先提醒到期复习，遵守 review_minutes 预算，只先展示回忆问题；我要求答案或作答后再提供答案，不代答、不替我自评。复习日期和已学状态由 App 或后端根据我的实际反馈维护。离线恢复时只处理当日预算，优先补复习，不累计发送多天提醒。

仅当出现新课程可学、未提醒的到期复习、首次出现或实质变化的候选需要我选择，或需要处理的失败时，才在当前任务通知我，并给出一个清楚的下一步。我还未选择但候选未变时，不重复催选。同日正常重复运行不重复通知；没有新动作、到期项或需要处理的失败时保持安静，不发送例行日报。准备好本次提醒内容后，按项目时区对应日期运行 ack-daily --date YYYY-MM-DD，避免重复；失败未完成的内容不要记为已提醒。

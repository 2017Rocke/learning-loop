# 安卓 APK：安装、课程更新和日历

安卓版将教学界面和初始课程装进 APK，安装后可离线学习。课程可以从自己的公开 GitHub 仓库更新；学习记录留在手机，更新课程通常不需要重新安装 APK。浏览器版本仍可使用，说明见 [手机网页](mobile.md)。

## 先在手机体验

需要 **Android 8.0 或以上**。优先从仓库 **Releases → Android 0.2.2 预览版** 下载 `.apk`，无需解压。开发者也可以从 **Actions → Build Android preview APK** 下载临时构建产物，但不要将其与 Release 安装包交替使用：签名可能不同。系统可能要求为当前文件管理器或浏览器允许安装应用，按手机提示操作。

这是 debug 预览构建，不是应用商店正式版。不同机器或不同次 CI 构建的调试签名可能不同，不能保证互相覆盖安装。已有学习记录时先在 App 中导出备份，避免卸载导致丢失。正式连续升级需要使用者保管的稳定签名密钥，不能把密钥提交到公开仓库或交到聊天中。

### 从 Release 0.2.1 更新到 0.2.2

0.2.2 修复部分安卓设备上语音只播放开头就报错的问题：本地媒体的非零字节范围曾被 App 与 WebView 重复定位，导致后续音频数据不正确。修复适用于内置和下载后的课程，也覆盖视频拖动。错误时增加“重新加载这段语音”按钮与可反馈的错误编号。课件本身和课程版本未改变；整课连续播放和后台播放不属于此次修复。

Releases 中的 0.2.2 沿用 Release 0.2.1 的签名，版本号递增，可以直接打开 APK 覆盖安装，保留学习记录、课程仓库和日历归属标记。更新前可导出备份；不需要卸载、清除数据或重建日历。若提示签名冲突，应保留旧版并核对下载来源，可能装的是 Actions 临时包。App 中的“检查更新”仍只更新课程，此修复需要安装新版 APK。

复测时保持 App 前台，先把贝叶斯“看懂原理”语音完整播放到约 1:28，再拖到中后段播放，并检查一段高斯讲解。若仍中断，记录错误提示中的编号及停止时间；实际手机是否恢复以复测为准。

### 从早期 Actions 0.2.0 换装 0.2.1

早期 Actions 0.2.0 与本次 Release 0.2.1 的签名不同，无法直接覆盖安装。App 里的“检查更新”仅更新课件，不能安装新 App。请按以下顺序换装：

1. 在旧版“我的 → 导出学习记录”保存 JSON 备份到手机“下载”等应用外目录，确认文件存在；记下“课程仓库”设置。
2. 下载新版 APK。只有确认备份已保存后，才卸载旧版并安装新版。
3. 新版首次询问日历时先选“暂不设置”，通过“我的 → 从手机文件恢复备份”导入刚才的文件，并重新设置课程仓库。日历授权也需要重新授予。
4. 卸载可能保留系统日历里的旧提醒，而日历去重标记属于旧 App 数据，不在学习记录备份中。如需再次同步，先在系统日历删除旧的“知行 · 每日回忆复习”整组重复日程及旧的“知行 · 课程到期复习”，再回 App 同步，避免重复提醒。也可先保留原提醒而暂不重新同步。

0.2.1 将小米本地日历名称显示为“本机日历”，并把“选择日历”与“同步提醒”分开：先看到单选状态，再点击明确的确认按钮才写入。

首次安装可以直接学习随包课程。要测试完整流程，需要手机 Android 版本、安装结果，以及图解、音频、更新和日历的实际表现；本地构建成功不等于真机验收完成。

## 将项目放到自己的 GitHub

1. 在 GitHub 官方网站登录，创建一个 **Public 公开空仓库**。不要勾选初始化 README、LICENSE 或 `.gitignore`，本项目已经包含这些文件和 Git 历史。
2. 复制新仓库的 HTTPS 地址。下面用 `OWNER/REPO` 作占位，必须换成自己的真实值；项目已经是 Git 仓库，不需要再次 `git init`。

```sh
git remote add origin https://github.com/OWNER/REPO.git
git push -u origin main
```

如果已配置 `origin`，先查看其地址再决定是否修改，不重复添加或覆盖未知远端。也可使用 GitHub Desktop 打开现有项目并发布为公开仓库。凭据只在 GitHub 官方或 GitHub Desktop 登录界面输入，不发送到聊天，不写进项目文件。

3. 首次使用时在仓库 **Actions** 页面确认工作流允许运行。**Publish Android courses** 在 `main` 的课件变化后运行，也可以手动触发；先查看 Actions 是否成功。
4. 在仓库 **Releases** 中确认固定标签 `course-content` 的发布包含 `manifest.json` 和 `courses-<hash>.zip`。只有远端文件实际出现后，手机才能检查并下载更新。

只需提供仓库 URL 和是否公开，就能核对配置。当前版本使用公开发布，不支持私有仓库；App 不需要 GitHub 登录、密码或 token。仓库提交和构建产物应只有公开课件与代码，不包含学习数据库和个人导出。

## 在 App 更新课程

1. 点击顶部“课程仓库”，填写 `OWNER/REPO`，例如 GitHub 地址中域名之后的“所有者/仓库名”。
2. 点击“检查更新”，App 先读取 `course-content` 发布中的小型清单，比较已安装课程版本。
3. 存在不同版本时显示“下载新课程”；点击并确认后才获取完整课程包。网络失败可以继续学习当前版本。
4. 完整下载、校验 SHA-256 和包内资源后，新课程准备就绪；先保存当前页面未提交的输入，再确认刷新。也可稍后刷新，旧页面继续使用原课程快照。失败保留原课程和学习档案。

配置好仓库后，每次重新启动 App 或保存仓库也会轻量检查小清单；不会自动下载完整课程。检查失败只影响更新状态，不阻断已有课程。

APK 版本决定界面和原生能力，课程版本决定教材、图解、音视频。增加教材通常只发布课程包；修改界面功能、原生权限或包格式时可能需要新 APK。课程更新不从 GitHub 下载或执行 JavaScript、HTML 或原生代码。

更新源是使用者选择的公开仓库。SHA-256 检查下载与该清单是否一致，不是对教材事实或仓库作者的认证。课程与问题 ID 应保持稳定，以便旧记录仍能对应。当前客户端会拒绝启用删除已有课程或题目的更新，继续保留原课库与记录；应让维护者发布保留原 ID 的完整课程包。

## 每次确认后写入手机日历

在“我的 → 手机日历提醒”点击“同步到手机日历”，先查看本次提醒内容，点“下一步：选择日历”，按需授予日历读写权限，然后选择一个可写日历。首次进入和更新课程后的刷新也会提供确认入口。最后点“同步提醒”，App 才会写入或更新同一条每日复习安排；重复操作不会不断增加同样的每日事件。

日历选项使用单选圆点：只有一个时默认选中；多个时需要主动选择，“同步提醒”按钮才可用。点击名称只改变选择，点击“取消”或返回不会写入。部分小米系统会返回 `calendar_displayname_local` 和 `account_name_local` 这样的内部名称，App 将这组名称显示为“本机日历”；其他日历保留实际名称和账号，便于区分。同步后请在系统日历查看“知行 · 每日回忆复习”；出现选择框只代表读到了可写日历，不代表已经创建提醒。

有真实复习计划时，另外按课程各取最早到期的一条，单次最多同步 20 门课程：未到期的保留实际时间，已过期的安排到下一个每日复习时段。不含你的答案。计划变化后需要再次确认同步；当前已不在复习表中的旧单次事件暂保留，可在系统日历管理，不宣称自动清除。

拒绝权限、取消确认或没有可写日历时，仍可继续学习，页面内仍显示到期复习。Android 权限获准不代表以后可以静默改日历，每次写入仍需要本次确认。若学习档案损坏，先保留原始备份并恢复有效记录，再同步日历，避免用空状态改写计划。是否弹出通知由手机日历及系统设置决定，不依赖 App 一直打开。

默认每日复习安排用于留出学习时间，具体到期题目仍以 App 为准。复习时刻来自课程清单的默认配置；分钟数已有本机偏好时使用本机值，否则使用清单默认值。日历只包含必要提醒和课程名称，不包含个人回答。选择云同步日历时，事件是否同步由该日历账号的设置决定；课程更新和 GitHub 不接收学习档案。

## 备份与换机

安卓版通过系统文件选择器导出、选择学习 JSON 备份，由用户决定保存位置。导入先验证，确认后整体替换本机记录，不合并、不上传 GitHub。更新课程不会替换个人档案；清除应用数据或卸载应用会丢失未导出的本地记录。

浏览器网页、安卓版 WebView 和电脑 SQLite 是独立存储。不要把更换安装包或登录 GitHub 当成自动同步；先备份，再在兼容的课程版本中导入。

## 维护者构建与发布

在项目根目录准备公开课程包和 APK 内置界面：

```sh
python3 scripts/build_android_content.py --output dist/android-content --assets android/app/src/main/assets/site
```

该命令先构建受信任的网页界面，再生成 `dist/android-content/manifest.json` 与 `courses-<hash>.zip`。APK 内置的界面随二进制发布；远程课程 ZIP 只装课程数据和允许的媒体资源。`content/reminder.json` 设置默认复习时段和分钟数，其变化也会改变课程版本，手机写入日历仍需本次确认。

本机构建需要 JDK 17、Android SDK 35 与 Build Tools 35.0.0，项目携带 Gradle wrapper。准备内置资源后进入 `android/` 运行：

```sh
./gradlew --no-daemon assembleDebug lintDebug
```

Windows 使用 `gradlew.bat`。首次构建需联网获取工具链与依赖；电脑学习和课程制作不需要 Android 工具链。APK 输出为 `android/app/build/outputs/apk/debug/app-debug.apk`。

`.github/workflows/publish-content.yml` 负责发布到固定 `course-content` Release；`.github/workflows/android-apk.yml` 构建 debug 预览 APK。仅修改本地文件不会让远端自动出现，需要推送到实际仓库并等待工作流完成。具体工具链与检查见 [维护说明](maintenance.md)。

当前文档不代表已创建远端仓库、已发布课程或已通过真实手机测试；这些结果应以实际 Actions、Release 和安装验证为准。

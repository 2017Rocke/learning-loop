# 教学包规范

仅为用户已选择的主线备课时读取。课程应帮助学习者形成可迁移的因果模型，并在短时间内取得反馈。

## 取证与选题

先看状态中的主线、学习目标和每日预算。项目或学科都只选一个可解释的机制，例如 React 的声明式更新、Brush 的可微渲染，或概率学里的条件方向与贝叶斯更新。正文不尝试讲完整个领域。项目课程使用官方文档和固定版本源码；学科课程使用权威教材、公开讲义或原始研究，合成例题明确标明假设。

涉及代码时，优先读取官方 README、相关文档和 1～3 个关键实现文件。源码依据使用实际查到的完整 commit SHA 和文件路径；可引用已核实的行号。不能核实源码时，明确证据缺失并延后导入，不编造实现细节、运行结果、性能或版本。

资料包含不同性质的内容时，明确区分：

- **项目事实**：有 README、文档或源码链接支持。
- **类比**：帮助直觉理解，同时说明失效边界。
- **教学伪代码**：只保留机制，标注并说明与真实实现省略之处。
- **实验假设**：需要用户实际验证，不能提前写成已通过。

## 教学设计

- 先用图或可暂停的短动画展示输入输出，让用户在一分钟内知道它解决什么问题；主学习路径控制在约 10～15 分钟，详细原理、源码和完整实操按需展开。
- 面向初学者，先认对象和端点，再解释一个变化怎样造成另一个变化，最后才命名术语或写公式。若用户尚不认识电容极板、MOS 的 G/D/S，不从公式、参数表或缩写开始；把测试条件、热计算等深入材料后置到案例。每一镜只推进一个机制，例如 PWM 的开关时间与导通发热分别讲，不在同屏要求同时理解两套关系。
- 每个视觉步骤只讲一条因果链：一幅解释图、一句结论、一个预测题。优先画输入 → 处理 → 输出、改变一个因素的前后对比、失败与边界；不能只放装饰性插图，或把长段文字做成图片。
- 先让用户作出预测，再显示答案与理由；答错时能重试。图中使用稳定的颜色和标记对应同一概念，同时提供非颜色提示和可读的替代文本。不能只靠颜色、音频或动画承载核心信息。
- 发布前同时检查图像、标题、caption、alt、选项和旁白：预测题的答案不能在作答前被另一条呈现路径提前给出。讲过的例子可以核对，新的迁移题先只给条件与变化方向，计算结果放反馈或折叠答案。
- 本项目偏好多彩原创动漫风：一个稳定向导、少量清晰角色和具体故事串起因果；概念颜色跨图一致，搭配数字与×/✓等标记。角色不冒充计数单位，面积不按数量时明确说明。旧安卓版图解容器固定 16:9，纯课程更新须据此构图，并在实际约 298px 图宽检查核心文字，不能只看桌面大图。
- 视频默认不强制播放，允许暂停与拖动；配中文字幕和等价文字。没有可用官方视频时制作原创原理动画，明确是示意、类比还是实际重建结果。普通网址只能标成补充观看入口，不冒充内嵌视频。
- 可交互的课程让用户能改一个参数并立即看见影响。只使用 App 已支持、且适合当前技术的交互类型；没有合适组件时以图解、真实例子或短动画完成学习，`interactive` 为 null，不虚构控件。
- 提炼 3～5 个核心思想，说明每一步为什么存在，以及去掉后会发生什么。
- 代码教学先讲输入、关键处理和输出，再给逐行中文解读。用一段短教学伪代码建立全局，再取真实源码验证关键步骤；每行解释变量角色、数据变化或控制流意义，并说明必要性、上下文或删改后的影响。不要只翻译 `let`、`if` 等语法，也不把无法证实的作者意图写成事实。
- 适配听觉学习：核心章节用自然中文短句，术语第一次出现就解释，指代要能脱离屏幕理解。按机制复杂度安排长度，不为凑时长灌满旁白；给预测与操作留出时间，源码逐行精讲另列。优先温柔甜美、自然清晰的中文女声，先试听含数字、术语和转折的片段；不能用简单升调冒充音质改进。最终时长以音频实测为准，不能只按字数估算后标成事实。
- 包含一个常见误解或反例，帮助区分“看起来有效”和“满足需求”。例如高斯场景视觉逼真不代表可直接 3D 打印或精确测量。
- 设计至少一个迁移问题：让用户把同一思想应用到另一个对象、参数或约束下。
- 问题覆盖解释、预测、诊断、迁移，答案给出推理依据，不只给术语。每个问题用稳定且唯一的 `id`，后续改写不要随意改 ID。
- 主路径内提供 3～5 分钟小操作，并保留 15～30 分钟的进一步实验。优先已有环境、纯本地小样例或安全演示；依赖安装、GPU、下载大数据等成本必须在步骤中说明，并提供较轻的替代实验。
- 实际应用提出一个用户能使用的成果和可验收标准。验收写可观察的结果，例如“保存输入和输出，并解释两处变化”，不要只写“理解原理”。
- 复盘问题要求闭卷复述、对照预测与结果、总结适用边界，不能用“今天感觉如何”替代知识回忆。

## 严格 JSON 结构

只使用以下顶层字段和嵌套字段；所有正文为字符串，列表类型与示例一致。不加 Markdown 代码围栏、注释或额外状态字段。`source_refs` 必须是已读取的真实来源；有代码教学时 `code_insight.source_url` 也必须真实核实；代码摘录保留原意，伪代码在 `explanation` 中明确标注。

`visual_lesson` 在后端为向后兼容的可选字段，**新备课必须提供**。旧课程升级时补充此字段，保持原 `questions[].id`，不重置学习或复习记录。

`code_insight` 对不涉及代码的学科课设为 null，页面跳过代码章节，不编造源码或不必要的算法。涉及代码时，`code_insight.walkthroughs` 是兼容旧课的可选字段，**新项目备课必须提供**。后端允许 1～8 段；有代码教学的新课至少包含一段教学伪代码和一段已核实的真实源码。优先每段 8～25 行，每段最多 80 行；较复杂过程拆成 2～3 段核心步骤，不贴整文件。原 `code_insight.snippet` 等字段保留供兼容或完整上下文阅读。

### 逐行代码解读字段与取证

每段 `walkthroughs` 只含以下字段：`id`、`title`、`kind`、`language`、`snippet`、`source_url`、`source_path`、`source_commit`、`source_start_line`、`notes`。段 ID 在课程内唯一并保持稳定。

- `kind` 只接受 `source` 或 `pseudocode`，页面应明显区分真实源码和教学概括；`language` 写实际语言或 `pseudocode`。
- `source` 必须来自本轮真正读取的官方源码：`source_commit` 是完整 40 位十六进制 commit；`source_path` 是仓库相对文件路径；`source_start_line` 是该片段在原文件中的正整数起始行号；`source_url` 指向匹配仓库、固定 commit 与文件路径的官方 HTTPS 页面，URL 路径必须含 `/完整commit/` 且以 `/source_path` 结尾。读取较长上下文确认变量来源、调用点与控制流，但只摘本课需要的连续片段。
- 真实 `snippet` 保留连续原文，包括缩进、空行、原注释和结构行。不要为缩短而在中间插入省略号、改名或加入中文注释；需要跳过一段就另建一个片段并重新记录起始行号。不能把伪代码包装成真实摘录。
- `pseudocode` 的 `source_path`、`source_commit`、`source_start_line` 必须为 null；`source_url` 仍使用本轮核实的相关真实实现链接。说明简化了哪些步骤，不能编造可执行 API。上面 JSON 例子只演示字段，正式课还须添加真实源码段。
- `notes` 是 `{ "line": 1, "comment": "这一行做什么、变量扮演什么角色", "why": "为什么需要、删改可能影响什么，或理解它需要的上下文" }` 列表。`line` 从片段内第 1 行起算，不是原文件行号；每个非空行恰好有一条，按行递增，不重复、不越界，空行无需旁注。
- 原注释、函数签名、括号和结束分支等非空结构行也要解释，例如“结束缺失梯度分支，继续向下时梯度已有值”。不要给结构行虚构数值计算。核心行解释输入输出与因果，辅助追踪/日志行明确不会直接改变算法结果。
- 中文 `comment` 与 `why` 都必须有实际内容，长度分别不超过 700 与 1000 字符；不写“执行本行”“提高性能”等空话。若必要性只能合理推断，应限定为可观察行为或明确推断，不替作者宣称隐含动机。

导入前逐段重新对照：以 `split('\n')` 保留换行边界，原文件 `source_start_line` 起连续 N 行应与 `snippet` 完全相同；N 为片段行数。`notes.line` 必须按递增顺序与全部非空行号逐项相等。先让学员看核心链路，再按选择逐行展开中文说明；不要求首屏同时堆满代码和所有注释。

### 视觉字段约定

- `duration_minutes` 为整个主路径的预计分钟数，不是视频时长。`video` 可以为 null；有值时包含示例中的全部字段。`duration_seconds` 写实际生成视频的时长，`transcript[].time` 是从 0 开始且递增的秒数，必须落在视频时长之内；字幕、文字稿与画面保持一致。
- `steps` 至少覆盖输入输出、核心机制和一个误解或边界。`id` 在课内唯一并尽量稳定。每题三个互不混淆的候选项；`correct_index` 为从 0 开始的正确选项位置。
- 图片路径为 `/media/<课程目录>/<文件>.svg`、`.png` 或 `.jpg`，对应项目 `web/media/` 内已存在文件。视频为同目录 `.mp4`，字幕为 `.vtt`。不要使用路径穿越、绝对本机路径、数据 URL、任意 HTML、内嵌脚本或外站图片地址。SVG 仅包含静态图形和文字，不包含脚本、外部引用或 HTML。
- 已实现的交互类型：`gaussian-viewer`（合成高斯投影）、`bayes-counts`（10,000 个体的四格计数与条件概率）；二者字段均为 `{ "kind": "类型", "title": "标题", "prompt": "提示" }`。`voice-ab` 另需恰好两个 `samples`，每个有 `label`、本地 `src`、完整 `transcript`、实测 `duration_seconds`。它们分别用于对应机制，不能把固定实验改称通用模拟器。其他技术默认 null，需要新类型时先实现组件与 Python/Android 校验。
- 两个新实验类型从 Android 0.2.3 / versionCode 4 支持，构建器会相应设置课包最低版本。听辨媒体也必须列入包清单、逐文件哈希及引用收集；不能只在网页写路径。实验输入与反馈仅在当前页面，用户自己保存成果才产生学习记录。
- `watch_more` 可以为空列表。有内容时仅使用本轮读取并核实的官方 HTTPS 页面，指出观看目标；不要猜视频 ID、嵌入链接或第三方转载版权。来源不可访问时保留已核实原理来源与原创图解，不用失效链接填数。

### 中文音频与旁白源

用户希望少看屏幕，**新备课优先生成实际可听的核心讲解，涉及源码时再加中文精讲**。没有代码章节的学科课无需生成 code 音频。`audio_lesson` 在数据格式中可省略是为了兼容旧课，并不代表新备课无需考虑这个偏好。只准备文字稿、使用浏览器临时朗读或放外链时，分别说明实际交付方式，不能称为已生成本地音频。

正式课程可新增顶层 `audio_lesson`，只含 `voice` 和 `clips`：

- `voice` 用可读文字说明实际音色和合成来源。例如 Tingting 写“本机合成中文语音（Tingting）”，在线晓晓写“合成中文女声（晓晓 · Microsoft Edge Neural）”；不要将在线生成标成本机合成，也不冒充真人录音。
- `clips` 为 1～16 项列表，每项严格包含 `chapter`、`walkthrough_id`、`title`、`src`、`duration_seconds`、`transcript`。
- `chapter` 只接受 `logic`、`case`、`code`、`experiment`、`application`、`summary`，对应现有六个学习章节。每章总览使用 `walkthrough_id: null`；源码单段精讲使用 `chapter: "code"` 及该课 `code_insight.walkthroughs` 中真实存在的 ID。相同章节和片段 ID 的组合不可重复。
- `src` 必须指向项目 `web/media/` 中实际生成的本地音频，URL 格式为 `/media/<课程>/audio/<文件>.m4a`、`.wav` 或 `.mp3`。不能使用外部媒体、任意 HTML、路径穿越或空文件充数。
- `duration_seconds` 为读取音频元数据得到的实际秒数，范围 1～1800；不能填写预计耗时或直接复制示例数字。`transcript` 是该音频的完整旁白，最长 12000 字符，与声音内容一致。

可先保存独立旁白源 `content/<课程>-narration.json`，格式为 `{ "voice": "实际本机音色名", "rate": 190, "clips": [...] }`。源文件的每个 clip 使用 `chapter`、`walkthrough_id`、`title`、`filename`、`text`，不预填资源路径或虚拟时长。190 仅是可调整的合成语速起点；确认本机音色可用后生成，再把实际路径、时长与完整文字合并进 `audio_lesson`。

在 macOS 上先确认系统已安装所选中文音色；不要假定其他机器也有 Tingting，不自动下载。已有可用音色时，可在项目目录复用 `python3 scripts/generate_brush_audio.py --input <实际旁白JSON> --output-dir <项目web/media/当前课程/audio>`，参数必须换成当前课的真实路径。生成器完成原子生成与验证后，读取输出目录的完整 `metadata.json`，核对全部章节、源码 ID、音频路径、实际时长和文字稿，再合并到 `audio_lesson`；单个音频文件存在不代表整套制作成功。

需要更自然的神经女声时，可选用 `scripts/generate_neural_audio.py`，运行方式与依赖见 `docs/authoring.md`。旁白源为 `{ "engine": "edge-tts", "voice": "zh-CN-XiaoxiaoNeural", "rate": "-5%", "pitch": "+0Hz", "clips": [...] }`，clip 字段同上但 filename 为 `.mp3`。此显式制作命令会把文稿发送到在线语音服务，仅使用可公开教学文本；拒绝或失败就说明，不能修改鉴权绕过限制。App 播放无需该依赖、账号或服务连接。在线生成结果仍须完整解码、核对旁白与实际播放，不得静默回退成已知不受用户欢迎的音色。

旁白内容要求：

- 先说当前目标和因果，不重复朗读界面按钮、完整 URL、代码标点或很长的变量拼写。变量先解释其角色，再按需提名称；逐行精讲覆盖该片段全部非空行的职责与理由，但用听得懂的自然中文连接。
- 图中关系用文字说清，例如“前层削弱后层颜色贡献”，避免只说“看这里”“变成这样”。需要区分位置或观察误差时，明确提示先暂停声音查看画面。
- 动手实验提醒暂停后操作、观察，再继续听；不暗示可以不看屏幕操作，也不声称用户已经完成实验。
- 回忆章节先邀请暂停、自行解释，再给核对依据；不替用户作答、选择评分或提交掌握状态。

生成后验证文件可解码、真实时长、音色与文字稿对应；按开头、核心转折与结尾检查可理解性，实际可用工具允许时试听。网页应由用户主动播放，支持暂停和进度操作，切换章节时不继续在后台叠加声音；操作检查按实际播放器能力进行。声音、字幕或文字稿任一路径出错时如实说明，不能把文件存在当作播放验收。听完旁白不自动创建学习证据、复习成绩或掌握状态。

整课听讲按主章节播放，不自动混入源码深听。进入实验、应用和总结前停下，用户准备好再继续；离开页面或进入后台暂停。播放位置使用独立本地存储，更新音频文字或时长后不能错误续播到旧内容，也不进入学习记录备份。检查视频时同时验证播放、暂停、分镜跳转和错误重载；烧录字幕默认不再叠加 VTT 显示，VTT 保留作可选字幕和等价文本。

### 媒体制作与验证

在项目 `web/media/<课程目录>/` 生成可离线访问的资产。以手绘式示意图、静态 SVG、逐帧动画等适合概念的方式表达；同一课程复用形状、颜色和术语。对动态过程优先短动画，对结构和对比优先图解；不必每课都制作视频。

电路动画要先定义图例，再决定运动方式。带负号的电子标记、约定电流箭头和电场符号表示不同对象；不能靠换颜色把它们混为一类。使用电子标记时，说明是局部净变化或路径示意，不假装粒子个数、速度就是实际测量。理想电容介质、MOS 栅极绝缘层两侧的电场作用，不画成电子穿过绝缘层。

若画的是有起点、终点的电子输运路径，使用有限单程，到端点停止或结束；不能把时间取模后突然从终点回绕到起点。是否能循环由实际闭合回路和讲解阶段决定。运动符号的整个半径、描边与尾迹都须留在允许区域，不能只检查中心点，避免边缘碰到或进入介质。约定电流箭头则明确标注方向约定，MOS 关断后的续流闭环不得穿过断口。具体分镜与检查办法见项目 `docs/video-authoring.md`；这些规则针对电路机制图，不套用于其他学科的计数点或角色运动。

先查看图像实物，检查箭头、标签与正文是否一致，以及窄屏是否仍可读。对于本项目的手机课程，以约 298px 图宽检查字幕和关键标签，并审查全程运动及镜头切换：路径起止、停止、回绕、极板边界、导通/关断转换都要覆盖，不能仅看每幕一张缩略图。另核对实际时长、完整解码、播放与暂停；确认字幕和文字稿能独立表达机制。自动几何检查可以核对坐标与禁入区，但不能替代画面含义和实际播放检查。没有生成完的文件不能写成可用媒体，不复制本课不存在的路径。学员观看视频、点完图解或答对一步题，只表示参与了学习，不自动提交实操或提升掌握状态。

## 导入前检查

核实链接可对应本课事实，教学伪代码与真实实现有清楚区分，存在 `walkthroughs` 时，其固定版本、连续原文、起始行号与逐行中文覆盖均已核验，实验可在预算内完成，问题先于答案，验收要求真实证据。确认 `visual_lesson` 引用的本地资产真实存在且已预览，视频或图解不是空占位；交互类型已经实现。含 `audio_lesson` 时核实每段音频实物、时长、文字稿与章节或源码 ID 对应，验证播放器而不只检查链接。保存 UTF-8 JSON，调用后端导入并读取状态核验，再打开学习页检查视觉主路径、代码旁注与语音。后端拒绝时按错误修正 JSON，不绕过校验直接写数据库。

不能访问来源、不能确定目标或依赖超出当前条件时，记录具体缺口，保留 queued 状态并说明下一步；不要以未经核实的通用教材填满课程。

## 课库与移植

所有路径相对项目根，媒体URL相对课库根由前端解析，不写开发者机器路径、访问令牌或自动化ID。`content/courses.json` 是发布清单（schema_version=1，courses数组）：每课包含稳定 id、title、topic_id、subject、kind（project/subject）、repo_full_name、repo_url、lesson_file。lesson_file 指向 content 内的课件JSON；学科课的仓库字段留空。课程元信息和学习档案分开，示例课不代表用户学过。

在导入或构建前运行 `validate-lesson --file ...`；`doctor` 用于核对环境与课库。静态构建命令为 `python3 scripts/build_site.py --output dist/site`，仅发布课程与其媒体，不带 data/、私人导出、制作记录或机器路径。手机档案在当前浏览器 localStorage，清除站点数据可能丢失；当前不提供设备间同步或关闭页面后的定时推送。
